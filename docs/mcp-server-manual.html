Overview

The MCP server lets an AI agent (Claude, or any MCP client) set a donkeycar's speed and lane while the computer-vision autopilot does the steering. The autopilot follows a yellow tape centreline at 20 Hz; the agent reads the camera and car state, then decides how fast to go, which lane to hold, and when to stop.

The agent is never in the steering loop, on purpose. An agent round trip takes a second or more, and at that cadence a line-following car would always be a segment behind the road.

What the agent can do:

  • Read the track description (loop or dead-end, lap length, centreline, side-lines, named lanes), as nominal guidance.
  • Learn which autopilot is driving and read the settings it runs with (colour window, scan row, steering, throttle range).
  • See the latest camera frame plus steering, throttle, line confidence and drive mode.
  • Set a throttle ceiling and a lane (by name or in inches).
  • Measure how far away something in the image is, in inches on the ground.
  • Start, stop and emergency-stop the car.

What it cannot do: steer directly, or make the car go faster than the autopilot thinks is safe. Traffic features (stop signs, obstacles, addresses) are not configured anywhere; the agent finds them in the camera image.

Requirements and installation

You need a car created from the cv_control template, a taped track, the optional mcp extra installed, and (for lane changes and distance measurement) a camera calibration.

1. Install the mcp extra

The mcp extra (mcp>=2.1,<3) is optional, so a normal car install does not have it. Without it, both server commands stop and tell you to install it.

uv pip install -e ".[pi,dev,mcp]"     # on the car, from a clone
uv pip install "donkeycar[pi,mcp]"    # on the car, from PyPI

Swap pi for pc or macos when running off the car.

2. Create or update the car

donkey createcar --path ~/mycar --template cv_control

For an existing car, pull the code, then refresh the car's copies of manage.py and config.py from inside the car directory:

cd ~/mycar
donkey update --template cv_control

Without --template it defaults to complete, the wrong app. myconfig.py is left alone, so check it for stale overrides. The one that bites is CV_CONTROLLER_OUTPUTS; it must be:

CV_CONTROLLER_OUTPUTS = ['pilot/steering', 'pilot/throttle', 'cv/image_array',
                         'cv/confidence', 'cv/line_detected']

An older three-item list silently drops line confidence, and every downstream reader sees None.

3. Describe the track in track.yml

donkey createcar puts a track.yml in the car directory. Edit it to match the track you built. It is the only place the track is described: nothing in config.py or myconfig.py describes it. Validation is strict: unknown fields are rejected.

name: Kitchen loop                 # optional: describes the track itself
description: Yellow centreline, white side tape.

cv_control:                        # required: what the CV autopilot needs
  continuous: false                # required: true for a loop
  lanes:                           # required: where the CAR sits, inches from the centreline
    left: -9.0                     # must be negative
    right: 9.0                     # must be positive
                                   # center is always 0 and is not configured

  lap_length_inches: 480.0         # optional: measured along the centreline

  centerline:                      # optional
    tape_color: yellow             # a label only
    width_inches: 1.0
    dashed: true

  side_lines:                      # optional; omit either side if it has none
    tape_color: white
    left_inches: 18.0              # distance from the centreline
    right_inches: 18.0

Only name and description sit at the top level. Everything else is under cv_control:, the section for the computer-vision template, so a template added later gets its own section instead of colliding. The agent learns which section to read from get_autopilot.

The track is a centreline, solid or dashed, with optional side-lines. Every distance is nominal: measure it once at a representative spot. Width and centreline position vary along the course, so the agent is told to measure real values from the frame with measure_ground_point.

A tape_color is only a label. The colour the follower actually matches is COLOR_THRESHOLD_LOW / COLOR_THRESHOLD_HIGH in myconfig.py, which the agent reads with cv_control-get_autopilot_config.

lanes must name left and right. The center lane is always the centreline (0); configuring it, even as 0, is refused. cv_control-set_control(lane="left" | "center" | "right") works on every track, and further named lanes are allowed. Write offsets as a person sees the track; the server handles the sign flip into the camera's pixel frame, and a lane with the wrong sign is refused.

More than one track: keep a file per track beside track.yml, such as track-garage.yml and track-office.yml, and choose one at start-up:

python manage.py drive --mcp --track=track-office.yml
donkey mcp --car ~/mycar --track track-office.yml

A relative path is taken from the car directory; an absolute path is used as given. A --track file that is not there stops the server from starting, naming the path it looked for.

No track file at all: the server still starts, gives the agent a default track with generic left, center and right lanes, and logs a warning naming the track.yml it looked for.

Upgrading an older car: a track.yml in an earlier shape is refused, naming what to change:

  • Fields other than name and description at the top level: move them under cv_control:.
  • color in centerline or side_lines: rename it tape_color.
  • Segment fields (segment_length_inches, cross_length_inches, segment_count, cross_colors, tape_width_inches, top-level tape_color): delete them.
  • center in lanes: delete it.

TRACK_CONTINUOUS, TRACK_LAP_LENGTH_INCHES and TRACK_LANES_INCHES in an old config.py or myconfig.py once described the track when there was no track.yml. They are ignored now: move their values into track.yml and delete them. The TRACK_SEGMENT_* constants are ignored too.

4. Calibrate the camera

A lane offset in inches only works once the car knows how many pixels an inch is worth. Print assets/checkerboard/calibration-checkerboard-9x6-1in-letter.pdf at 100% / actual size, check that 10 squares measure 10 inches, and mount it flat on something rigid.

donkey calibrate-cv --car ~/mycar --forward-inches 24 --lateral-inches 0

Open http://localhost:8892, lay the board flat on the floor across the blue scan band, wait for green corners, and press Capture. It writes cv_calibration.json next to the config.

  • No printer: donkey calibrate-cv --car ~/mycar --tape-separation-inches 10 with two tape strips 10 inches apart. This gives scale only, so lanes work but measure_ground_point does not.
  • Centre lane only: no calibration needed, because zero inches is zero pixels.
  • Recalibrate whenever the camera moves.

Optional: calibrate the camera itself. The floor calibration above is all lane changes and measure_ground_point need. Measuring an object by its known size also needs the camera's focal length and lens distortion; without this calibration, measure_object_distance and estimate_speed_from_object answer known: false.

donkey calibrate-cv --car ~/mycar --intrinsics

Open http://localhost:8892 and hold the board up in front of the camera, not flat on the floor. Press Add view when the corners turn green, then move or tilt it and add another: tilted every way, near and far, in every part of the frame, corners included. After at least 12 views (15–20 is better), press Solve; it writes camera_intrinsics.json.

  • A good capture is well under 0.5 px RMS. Solve refuses, saying what to fix, with fewer than 12 views, an empty quadrant of the frame, or over 1 px RMS.
  • Every view is kept in camera_calibration_views/<date-time>/ in the car directory, with a views.json recording each view's error. Nothing deletes old folders.
  • Re-solve from a saved folder, with no camera: donkey calibrate-cv --car ~/mycar --from-images <folder>.
  • Re-mounting the camera needs only the floor calibration. Redo this one after changing IMAGE_W, IMAGE_H or CAMERA_TYPE, or swapping the camera or lens.

To tune the tape colour for your lighting, run donkey calibrate-color --images "~/frames/*.jpg" --compare on a few saved frames and watch the concentration figure.

Starting the server

Run donkey mcp --car ~/mycar for normal use; it gives the agent real start/stop control. Either way the server speaks streamable HTTP at http://<host>:8891/mcp, and the car stays still until the agent calls start and then sets a throttle.

Tuning without restarting

start re-reads config.py and myconfig.py, so the tuning loop is: edit myconfig.py → call stop → call start → look at the next cv_control-get_vehicle_state. A config that fails to parse fails the start and keeps the previous settings.

Two things need a real process restart (pkill -f "donkey mcp", then relaunch):

  • Changing MCP_SERVER_HOST, MCP_SERVER_PORT, MCP_SERVER_TOKEN or MCP_SERVER_ALLOWED_HOSTS, because the server is already listening with the old ones.
  • Changing manage.py, because the builder module is imported once. Config values reload; code does not.

Connecting a client

Any MCP client that supports the streamable HTTP transport can connect to http://<car-address>:8891/mcp. The server registers as donkeycar and sends instructions describing the rules below, so a capable agent learns them on connect.

From a laptop, first set a token in the car's myconfig.py, then make the car reachable by binding to its LAN address:

MCP_SERVER_TOKEN = "a-long-random-string"   # e.g. python -c "import secrets; print(secrets.token_urlsafe(32))"
donkey mcp --car ~/mycar --host 192.168.1.42

Claude Code:

claude mcp add --transport http donkeycar http://192.168.1.42:8891/mcp \
  --header "Authorization: Bearer a-long-random-string"

Other clients (Claude Desktop, MCP Inspector, custom code) take the same URL with the HTTP transport. A minimal JSON config entry:

{
  "mcpServers": {
    "donkeycar": {
      "type": "http",
      "url": "http://192.168.1.42:8891/mcp",
      "headers": { "Authorization": "Bearer a-long-random-string" }
    }
  }
}

Security

The port can make a vehicle move; treat it as a control surface. Two things guard it.

  • A token. With MCP_SERVER_TOKEN set, every request must carry Authorization: Bearer <token>; anything else gets 401. Without one, anyone who can reach the port can drive the car, and the server warns at startup when it is bound beyond 127.0.0.1. Keep the token in myconfig.py only: there is deliberately no command-line flag, which would put it in ps output and shell history.
  • A host check. A request's Host header must be a name the car answers to: localhost, 127.0.0.1, the machine's hostname with and without .local, and the bind address (or, bound to 0.0.0.0, every address the machine reports for itself). This is DNS-rebinding protection: it stops a web page in someone's browser from pointing its own domain at the car. A client using another name gets 421 naming it; add that name to MCP_SERVER_ALLOWED_HOSTS.

The server speaks plain HTTP, so the token crosses the network unencrypted. It keeps out a guest on the WiFi, not someone capturing its traffic. Prefer the car's LAN address over 0.0.0.0, and keep the car on a network you trust.

Tools reference

The server exposes ten tools. Those specific to the computer-vision autopilot start with cv_control- (its name and a dash), so a future autopilot can add its own without colliding. No other tool name contains a dash, so a name without one (get_autopilot, start, stop, emergency_stop, measure_ground_point) applies to any autopilot. Errors the agent can fix (an unknown lane, a missing calibration, a pixel outside the frame) come back as readable tool errors that say what to do.

The camera frame

The frame is not a field in the JSON. cv_control-get_vehicle_state returns a list of MCP content blocks:

  1. A text block holding the JSON state above.
  2. An image block (type: "image", mimeType: "image/jpeg", base64 data) holding the latest frame.

The image block is left out when the loop is not live (live: false) or no frame has arrived yet, so a stopped car never shows a stale picture. Check for it rather than assuming it is there.

  • Which image: the CV controller's output (cv/image_array) when present, otherwise the raw camera (cam/image_array). With OVERLAY_IMAGE = True it carries the follower's scan-band overlay.
  • Size: the camera's native resolution (320×240 on a stock car). Use these pixel coordinates for measure_ground_point.
  • Freshness: it is encoded on each request, not every loop. Compare loop_count between calls to tell a new frame from a repeat.

Three rules every agent must follow

  1. Throttle is a ceiling, not a command. The applied throttle is min(your throttle, autopilot throttle). A high value does not make the car corner faster; a low value slows it; 0 always stops it. Negative (reverse) passes through uncapped.
  2. Commands expire. If no cv_control-set_control arrives for MCP_COMMAND_TIMEOUT_S (2 s), throttle goes to zero. Reading state does not reset the timer. Re-send cv_control-set_control at least once a second while driving; re-sending the same values is the normal way to hold speed.
  3. Check line_detected before trusting steering. Full lock means "following a bend" when the line is visible and "driving blind" when it is not. While blind, steering decays to centre but the car keeps moving until you set throttle to 0.

Typical workflows

A first drive

  1. get_autopilot, then cv_control-get_track_config once, to learn lanes and whether the track loops.
  2. cv_control-get_calibration: check calibrated, stale and can_measure_points.
  3. start. The car arms in autopilot mode with throttle 0.
  4. cv_control-get_vehicle_state until line_detected is true. Camera auto-exposure can take a few seconds to settle after start.
  5. cv_control-set_control(throttle=0.3), then re-send it at least every second.
  6. Each tick: read state, look at the frame, re-send cv_control-set_control.
  7. To finish: cv_control-set_control(throttle=0), then stop.

Changing lane

cv_control-set_control(throttle=0.3, lane="right")
cv_control-set_control(throttle=0.3, lane_offset_inches=6)

Give lane or lane_offset_inches, never both. Any non-zero offset needs a pixels-per-inch calibration.

Stopping for something in the image

  1. Spot the sign or obstacle in the frame from cv_control-get_vehicle_state, and note that call's timestamp.
  2. If you know its size, call measure_object_distance with a tight box round it. If that answers known: false, call measure_ground_point on the pixel where it meets the floor (its base, not its middle) to get forward_inches.
  3. For speed, box it again in a frame at least half a second later and call estimate_speed_from_object with both {timestamp, box} pairs.
  4. Lower the throttle as distance falls, then cv_control-set_control(throttle=0) at your stopping distance.
  5. Keep sending throttle=0 while waiting, then resume with a positive value.

Accuracy drops toward the frame edges for both tools. measure_object_distance assumes the object is upright and turned roughly toward the camera, and its uncertainty assumes each box edge is within 1 pixel; widen it for a rougher box.

Tuning loop

Edit myconfig.py → stop → start → cv_control-get_vehicle_state. Useful knobs: COLOR_THRESHOLD_LOW/HIGH, CONFIDENCE_THRESHOLD (fraction of the scan column, default 0.15), SCAN_Y, SCAN_HEIGHT, TARGET_PIXEL, TARGET_THRESHOLD, THROTTLE_MIN/MAX. cv_control-get_autopilot_config shows the values the car is actually running with.

Testing without a car

Set CAMERA_TYPE = 'MOCK' (or 'IMAGE_LIST' with recorded footage) and DRIVE_TRAIN_TYPE = 'None', then connect a client to the server as usual.

Safety and field notes

The server is built so that silence, errors and stops all end with throttle at zero.

  • Nothing moves until start and a positive throttle. start arms with throttle 0.
  • stop zeroes throttle before tearing down, so the car cannot coast on its last value while parts shut down.
  • emergency_stop is instant and leaves the loop running, so you can resume without a rebuild.
  • No throttle before the autopilot has one. Until the CV controller produces a throttle, the ceiling resolves to 0.
  • There is no way to bypass the ceiling from the tool surface, deliberately.
  • Keep a hand near the car for the first runs. The watchdog covers agent silence, not a bad decision.

Lessons from a real track:

  • A car that will not move or will not turn is usually a PWM range too narrow for the hardware. Convert PWM counts to microseconds before changing anything else.
  • Too low a THROTTLE_MIN lets the car stop in a corner and fail to restart, because starting needs more than rolling.
  • Print the track cards and checkerboard on matte paper; glossy stock throws a highlight that blows out the detail a camera needs.
  • Dashed tape never fills the scan band, so confidence sits lower than solid tape; check real frames before lowering CONFIDENCE_THRESHOLD.

Troubleshooting

Older cars: if the server refuses to launch, naming fields in track.yml, the file predates the current format. Make the change the message names; see Requirements, step 3.
